# Изменения в системе

## Основные изменения

### 1. Объединение таблиц users и workers
- Создана единая таблица `users` с полем `role`
- Роли: клиент, менеджер, курьер, администратор
- Добавлено поле `delivery_address` для адреса доставки
- Создана миграция `merge_users_workers.py` для объединения данных

### 2. JWT аутентификация
- Реализована JWT аутентификация в `app/core/security.py`
- Токены хранятся в cookie `access_token`
- Срок действия токена: 7 дней

### 3. Единая форма входа/регистрации
- Убрана возможность выбора роли при регистрации
- Все пользователи регистрируются как "клиент" по умолчанию
- Единая форма входа для всех ролей

### 4. Личные кабинеты
Созданы отдельные страницы для каждой роли:

#### Администратор (`/account/admin`)
- CRUD операции для всех таблиц БД (блюда, пользователи, заказы, ингредиенты)
- Просмотр списка всех пользователей, курьеров, менеджеров
- Полный доступ к управлению системой

#### Менеджер (`/account/manager`)
- Просмотр и поиск заказов
- Назначение курьера на заказ
- Отмена доставки

#### Курьер (`/account/courier`)
- Список назначенных заказов
- Просмотр содержимого заказа
- Изменение статуса заказа

#### Клиент (`/account/client`)
- Просмотр истории заказов
- Редактирование профиля

### 5. Валидация полей
- Проверка обязательных полей при регистрации
- Проверка адреса доставки при оформлении заказа
- Если адрес указан в профиле, он используется автоматически

### 6. Скрипт обновления ролей
Создан скрипт `update_roles.py` для массового обновления ролей пользователей:
- Массивы логинов для каждой роли (админы, менеджеры, курьеры)
- Запуск: `python update_roles.py`

### 7. Навигация
- В шапке отображается логин и роль пользователя
- Кнопка "Личный кабинет" ведет на соответствующую страницу
- Кнопка "Вернуться к меню" в личном кабинете
- Кнопка "Справка" с информацией о системе

## Технические детали

### Новые зависимости
- `PyJWT~=2.8.0`
- `python-jose[cryptography]~=3.3.0`

### Изменения в моделях
- `User` теперь содержит поле `role` и `delivery_address`
- `Order` использует `courier_id` вместо `worker_id`

### API маршруты
- `/login` - единый вход
- `/register` - регистрация
- `/logout` - выход
- `/account/{role}` - личные кабинеты
- `/checkout` - оформление заказа (с проверкой адреса)

## Миграция базы данных

Для применения изменений необходимо:
1. Запустить миграцию: `alembic upgrade head`
2. Обновить роли пользователей: `python update_roles.py`

## Примечания

- Старая таблица `workers` будет удалена после миграции
- Все существующие пользователи и работники будут объединены в таблицу `users`
- Роли работников будут сохранены при миграции
